1.1 Why software engineering matters Important

Banks, power grids, phones, cars, hospitals, films and games all run on software. Because so much depends on it, building software is a serious professional job, and that job is software engineering.

  • The economies of ALL developed nations are dependent on software. Infrastructure, utilities, manufacturing and the financial system are all computer-controlled.
  • More and more systems are software controlled: most electrical products now contain a computer and controlling software.
  • Software engineering is concerned with theories, methods and tools for professional software development.
  • Expenditure on software is a significant fraction of GNP (Gross National Product, the total value a country produces) in all developed countries.

Software costs

  • Software costs often dominate computer system costs. The software on a PC often costs more than the hardware.
  • Software costs more to maintain than it does to develop. For systems with a long life, maintenance costs may be several times development costs.
  • So software engineering is concerned with cost-effective software development.

Why do software projects fail? Must know

Many software projects still go wrong. Sommerville traces most "software failures" to two factors:

  1. Increasing system complexity: new software engineering techniques let us build larger, more complex systems, and then the demands change. Systems have to be built and delivered more quickly, larger and even more complex systems are required, and systems need new capabilities that were previously thought impossible.
  2. Failure to use software engineering methods: it is fairly easy to write programs without software engineering methods. Many companies have drifted into software development as their products and services evolved, and they do not use these methods in their everyday work. Consequently, their software is often more expensive and less reliable than it should be.

1.2 Professional software development Must know

Lots of people write programs for themselves, but most software development is a professional activity: software built for business purposes, for inclusion in other devices, or as software products.

Professional software is intended for use by someone other than its developer, is usually built by teams rather than individuals, and is maintained and changed throughout its life. Software engineering supports this kind of development (not individual programming) with techniques for specification, design and evolution.

What is "software"? Must know

Software: computer programs and associated documentation. Software products may be developed for a particular customer or may be developed for a general market.

So software is not just programs. It also includes the documentation, libraries, support websites and configuration data that make them useful: separate programs, configuration files, system documentation (the system's structure), user documentation (how to use it) and product websites. A personal program needs none of this, because nobody else will use or change it.

1.3 Software products and product specification Must know

Software engineers are concerned with developing software products, which is software that can be sold to a customer. There are two kinds:

Generic productsCustomized (bespoke) products
WhatStand-alone systems that are marketed and sold to any customer who wishes to buy them.Software that is commissioned by a specific customer to meet their own needs; a contractor builds it especially for them.
ExamplesPC software such as graphics programs and project management tools; CAD software; software for specific markets such as appointments systems for dentists; mobile apps.Embedded control systems, air traffic control software, traffic monitoring systems; systems supporting one particular business process.
Product specificationThe specification of what the software should do is owned by the software developer, and decisions on software change are made by the developer.The specification is owned by the customer for the software, and they make decisions on the software changes that are required.

Generic software is like a ready-made shirt: the maker decides the design, and can rethink it if development runs into problems. Customized software is like a tailor-made suit: the customer supplies the measurements (the specification) and the developers must work to them. The line is becoming blurred: many systems start from a generic product adapted for one customer, e.g. ERP (Enterprise Resource Planning) systems from SAP and Oracle, configured with a company's business rules, processes and reports.

1.4 Essential attributes of good software Must know

Good software must first deliver the required functionality and performance. Beyond that, quality covers how it behaves while running and how its code and documents are structured. These are its quality or non-functional attributes, e.g. response time or how understandable the code is. The ones that matter most depend on the application: an aircraft control system must be safe, a game responsive, a telephone switch reliable. In general there are four:

Product characteristicDescription
MaintainabilitySoftware should be written in such a way that it can evolve to meet the changing needs of customers. This is a critical attribute because software change is an inevitable requirement of a changing business environment.
Dependability and securitySoftware dependability includes a range of characteristics, including reliability, security and safety. Dependable software should not cause physical or economic damage in the event of system failure. Malicious users should not be able to access or damage the system.
EfficiencySoftware should not make wasteful use of system resources such as memory and processor cycles. Efficiency therefore includes responsiveness, processing time, memory utilisation, etc.
AcceptabilitySoftware must be acceptable to the type of users for which it is designed. This means that it must be understandable, usable and compatible with other systems that they use.

M-D-E-A: "My Dog Eats Apples": Maintainability, Dependability & security, Efficiency, Acceptability. Example: for the insulin pump, dependability (safety, reliability) matters most; for Mentcare, security of patient records and acceptability to busy clinicians.

The FAQ says "maintainable, dependable and usable", but the expected list has four names: Maintainability, Dependability and security, Efficiency, Acceptability. Dependability covers reliability, security and safety.

1.5 What is software engineering? Must know

Software engineering: an engineering discipline that is concerned with all aspects of software production, from the early stages of system specification through to maintaining the system after it has gone into use.

Key phrase 1: Engineering discipline

Using appropriate theories and methods to solve problems, bearing in mind organisational and financial constraints.

Key phrase 2: All aspects of software production

Not just the technical process of development. It also includes project management and developing tools, methods and theories to support software production.

Engineering means getting results of the required quality within schedule and budget, which often needs compromises. A systematic, organised approach is usually best, but a more flexible process suits web-based systems and mobile apps.

Importance of software engineering Must know

  1. Society depends on software: more and more, individuals and society rely on advanced software systems. We need to be able to produce reliable and trustworthy systems economically and quickly.
  2. It is cheaper in the long run to use software engineering methods and techniques than to write programs as if it was a personal programming project. For most types of system, the majority of costs are the costs of changing the software after it has gone into use.

Software process activities Must know

A software process is a sequence of activities that leads to the production of a software product. Four fundamental activities are common to all software processes:

  1. Software specification: customers and engineers define the software that is to be produced and the constraints on its operation.
  2. Software development: the software is designed and programmed.
  3. Software validation: the software is checked to ensure that it is what the customer requires.
  4. Software evolution: the software is modified to reflect changing customer and market requirements.

Systems organise these activities differently: aircraft software is completely specified before development begins, while e-commerce specifications and programs are developed together (Chapter 2).

S-D-V-E: "Some Developers Value Evolution": Specification, Development, Validation, Evolution.

Software engineering vs computer science vs system engineering Must know

  • Computer science is concerned with the theories and methods that underlie computers and software (theory and fundamentals). It is essential background, as physics is for electrical engineers, but its theories rarely fit large, complex problems.
  • Software engineering is concerned with the practical problems of producing software, i.e. developing and delivering useful software.
  • System engineering is concerned with all aspects of developing and evolving complex systems where software plays a major role: hardware development, policy and process design, system deployment and software engineering. System engineers specify the system, define its overall architecture and integrate the parts. Software engineering is part of system engineering.

1.6 General issues that affect software Must know

No method suits every type of software, but four related issues affect many different types:

IssueMeaning, and the challenge it creates
HeterogeneityIncreasingly, systems are required to operate as distributed systems across networks that include different types of computer and mobile devices, and must often integrate with older legacy systems in other languages. Challenge: dependable software flexible enough to cope.
Business and social changeBusiness and society are changing incredibly quickly as emerging economies develop and new technologies become available. They need to change their existing software and rapidly develop new software. Challenge: traditional techniques are slow and must deliver value sooner.
Security and trustAs software is intertwined with all aspects of our lives, it is essential that we can trust that software, especially remote systems used through web pages or web services. Challenge: stop malicious attacks and keep information secure.
ScaleSoftware has to be developed across a very wide range of scales, from very small embedded systems in portable or wearable devices to Internet-scale, cloud-based systems that serve a global community.

"Hungry Bears Steal Snacks": Heterogeneity, Business & social change, Security & trust, Scale. They match the FAQ's key challenges: coping with increasing diversity, demands for reduced delivery times and developing trustworthy software.

1.7 Software engineering diversity and application types Must know

  • There are many different types of software system, and there is no universal set of software techniques that is applicable to all of them.
  • The methods and tools used depend on the type of application being developed, the requirements of the customer and the background of the development team. The type of application is the most significant factor.

The eight application types Must know

TypeWhat it isExamples
1. Stand-alone applicationsRun on a local computer such as a PC (or as mobile apps). They include all necessary functionality and do not need a network.Office software, CAD programs, photo editors
2. Interactive transaction-based applicationsExecute on a remote computer and are accessed by users from their own PCs, phones or terminals; often update a large data store in each transaction.Web applications such as e-commerce; cloud mail
3. Embedded control systemsSoftware that controls and manages hardware devices. Numerically, there are probably more embedded systems than any other type.Phone software, car anti-lock brakes, microwave oven, insulin pump
4. Batch processing systemsBusiness systems that process data in large batches: large numbers of individual inputs create corresponding outputs.Phone billing, salary payment
5. Entertainment systemsPrimarily for personal use, intended to entertain the user. Quality of user interaction matters most.Computer and console games
6. Systems for modelling and simulationDeveloped by scientists and engineers to model physical processes or situations with many separate, interacting objects; often need high-performance parallel computers.Scientific simulations of physical processes
7. Data collection systemsCollect data from their environment using sensors and send it to other systems for processing; often in hostile places (inside an engine, remote areas).Wilderness weather station
8. Systems of systemsSystems composed of a number of other software systems, some generic (e.g. ERP), some specially written; used by large organisations.A company-wide system built from an ERP package plus custom systems

"Some Indian Engineers Build Excellent Models During Summer": Stand-alone, Interactive transaction-based, Embedded control, Batch, Entertainment, Modelling & simulation, Data collection, Systems of systems.

The boundaries are blurred (a phone game faces the same power limits as phone software), but each type needs its own techniques. A car's safety-critical embedded system is burned into ROM, so it needs extensive verification before sale; an interactive web app suits iterative delivery from reusable components; a system of systems needs its interactions specified in detail in advance.

Software engineering fundamentals Must know

Some fundamental principles apply to all types of software system, whatever development techniques are used:

  1. Managed process: systems should be developed using a managed and understood development process (different processes suit different types of software).
  2. Dependability and performance are important for all types of system: no failures, available when needed, safe, secure and not wasteful.
  3. Requirements: understanding and managing the software specification and requirements (what the software should do) are important.
  4. Reuse: where appropriate, reuse software that has already been developed rather than write new software.

"Proper Design Requires Reuse": Process, Dependability (& performance), Requirements, Reuse.

1.8 Internet (web-based) software engineering Important

  • The Web is now a platform for running applications, and organisations are increasingly developing web-based systems rather than local systems.
  • Web services allow application functionality to be accessed over the web.
  • Cloud computing is an approach to providing computer services where applications run remotely on the "cloud" (a huge number of linked computers shared by many users). Users do not buy software but pay according to use.

Before the web, business software was monolithic (single programs on single computers); now it is deployed on web servers, delivered as software as a service (e.g. Google Apps, Office 365), highly distributed and built by reuse. Four changes followed:

ChangeMeaning
Software reuseReuse is the dominant approach for constructing web-based systems: you think about how to assemble them from pre-existing software components and systems.
Incremental and agile developmentWeb-based systems should be developed and delivered incrementally; it is impractical to specify all their requirements in advance.
Service-oriented systemsSoftware may be built using service-oriented software engineering, where the components are stand-alone web services.
Rich interfacesInterface technologies such as AJAX and HTML5 support rich interfaces within a web browser.

Web-based systems are complex distributed systems, but the fundamental ideas of software engineering apply to them in the same way as to any other type of system. Memory trick: "Reuse It, Serve it Rich" = Reuse, Incremental, Service-oriented, Rich interfaces.

1.9 Software engineering ethics Must know

  • Software engineering involves wider responsibilities than simply the application of technical skills.
  • Software engineers must behave in an honest and ethically responsible way if they are to be respected as professionals.
  • Ethical behaviour is more than simply upholding the law; it involves following a set of principles that are morally correct.

Issues of professional responsibility Must know

In these areas, acceptable behaviour is set by professional responsibility rather than by laws:

IssueWhat the engineer should doExample
ConfidentialityRespect the confidentiality of employers or clients, whether or not a formal confidentiality agreement has been signed.Not discussing a client's unreleased product
CompetenceDo not misrepresent your level of competence or knowingly accept work outside your competence.Not posing as a security expert to win a contract
Intellectual property rightsKnow the local laws on patents, copyright, etc. and protect the intellectual property of employers and clients.Not reusing one client's code for another
Computer misuseDo not use technical skills to misuse other people's computers. Misuse ranges from trivial (game playing on an employer's machine) to extremely serious (dissemination of viruses).Not reading others' files with admin access

"Careful Coders Inspect Code": Confidentiality, Competence, Intellectual property rights, Computer misuse.

The ACM/IEEE Code of Ethics Must know

  • The professional societies in the US (ACM and IEEE) have cooperated to produce a code of ethical practice: the Software Engineering Code of Ethics and Professional Practice. Other bodies, such as the British Computer Society, publish similar codes.
  • Members of these organisations sign up to the code of practice when they join.
  • The Code contains eight Principles related to the behaviour of and decisions made by professional software engineers, including practitioners, educators, managers, supervisors and policy makers, as well as trainees and students.

Rationale: computers have a central and growing role in commerce, industry, government, medicine, education, entertainment and society. Software engineers take part (directly or by teaching) in analysing, specifying, designing, developing, certifying, maintaining and testing software, so they have significant opportunities to do good or cause harm, or to enable or influence others to. To ensure their efforts are used for good, they must commit to making software engineering a beneficial and respected profession.

Preamble: the short version states aspirations at a high level; the full version's clauses give details. Without aspirations, details become legalistic and tedious; without details, aspirations become high-sounding but empty; together they form a cohesive code. Committed to the health, safety and welfare of the public, software engineers shall adhere to eight principles:

PrincipleExact wording (learn this)In plain words
1. PUBLICSoftware engineers shall act consistently with the public interest.Public safety first; never hide a harmful defect
2. CLIENT AND EMPLOYERSoftware engineers shall act in a manner that is in the best interests of their client and employer consistent with the public interest.Be loyal to them, but not at the public's expense
3. PRODUCTSoftware engineers shall ensure that their products and related modifications meet the highest professional standards possible.Test properly; never ship poor work knowingly
4. JUDGMENTSoftware engineers shall maintain integrity and independence in their professional judgment.Honest opinions; don't sign what you haven't checked
5. MANAGEMENTSoftware engineering managers and leaders shall subscribe to and promote an ethical approach to the management of software development and maintenance.Realistic plans; no pressure to cut ethical corners
6. PROFESSIONSoftware engineers shall advance the integrity and reputation of the profession consistent with the public interest.Act so people trust software engineers
7. COLLEAGUESSoftware engineers shall be fair to and supportive of their colleagues.Credit others' work; help newcomers
8. SELFSoftware engineers shall participate in lifelong learning regarding the practice of their profession and shall promote an ethical approach to the practice of the profession.Keep learning; practise ethics yourself

Take the principles in pairs: PC · PJ · MP · CS, "A PC in PJs meets an MP from CS". That gives Public–Client, Product–Judgment, Management–Profession, Colleagues–Self. Each pair is one verb: whom you serve, what you deliver, how you lead, how you grow.

Ethical dilemmas Important

An ethical dilemma is a situation with no clearly right choice, common when people have different views and objectives. The slides give three examples:

  1. Disagreement in principle with the policies of senior management. Argue your case from within, or resign on principle? When should you report project problems? Too early may be overreacting; too late may make them impossible to fix.
  2. Your employer acts unethically and releases a safety-critical system without finishing the testing (e.g. falsifies safety validation records). Keep confidentiality, or alert the customer or the public? There are no absolutes in safety: disclosure may harm the employer and colleagues, silence may harm others. Weigh the potential damage, its extent and who is affected; go public only if it is very dangerous, and first try to resolve it while respecting the employer's rights.
  3. Participation in the development of military weapons systems or nuclear systems. Views differ, so employers and employees should make their views known to each other in advance.

For a 10M "code of ethics" answer: what the code is and who it covers → rationale (2–3 lines) → preamble idea (aspirations + details) → all eight principles in their wording → one dilemma. If the question says "professional responsibility", add confidentiality, competence, IPR and computer misuse.

1.10 Case studies used throughout the course Important

Sommerville uses four different types of system as examples, because software engineering practice depends on the type of system. Slide 2 says three, but slide 36 introduces four, and later chapters keep returning to all of them.

1. Insulin pump control system Important

An embedded system in an insulin pump used by diabetics to maintain blood glucose control. In diabetes the pancreas cannot make enough insulin; the pump simulates the pancreas:

  • It collects data from a blood sugar sensor and calculates the amount of insulin required to be injected.
  • The calculation is based on the rate of change of blood sugar levels.
  • It sends signals to a micro-pump to deliver the correct dose (one pulse = one unit of insulin).
  • It is safety-critical: low blood sugar can lead to brain malfunctioning, coma and death; high blood sugar has long-term consequences such as eye and kidney damage.

A sensor measures a blood parameter (electrical conductivity) that depends on the sugar level; the controller works out the dose and pulses the pump. The UML activity model shows how the software turns a sensor reading into pump commands:

Essential high-level requirements: (1) the system shall be available to deliver insulin when required; (2) the system shall perform reliably and deliver the correct amount of insulin to counteract the current level of blood sugar. The system must therefore be designed and implemented to ensure that it always meets these requirements.

2. Mentcare: a patient information system for mental health care Important

  • A medical information system that maintains information about patients suffering from mental health problems and the treatments they have received.
  • Most patients do not need hospital treatment but regularly attend specialist clinics, which are also held in local medical practices or community centres.
  • Intended for use in clinics, it uses a centralised database of patient information but can also run on a PC at sites without secure network connectivity.
  • With secure network access it uses the database; when disconnected it can download and use local copies of patient records.

Goals: (1) to generate management information that allows health service managers to assess performance against local and government targets; (2) to provide medical staff with timely information to support the treatment of patients.

Key features: individual care management: clinicians create, edit and view patient records and history, and data summaries let doctors quickly learn the key problems and prescribed treatments. Patient monitoring: the system monitors the records of patients in treatment and issues warnings if possible problems are detected. Administrative reporting: monthly management reports on patients treated at each clinic, patients entering and leaving the care system, patients sectioned (confined to a secure hospital), and drugs prescribed and their costs.

Concerns: privacy: patient information must be confidential and never disclosed to anyone apart from authorised medical staff and the patient. Safety: some patients may become suicidal or a danger to others, so the system should warn medical staff wherever possible. It must also be available when needed, or safety may be compromised and correct medication may be impossible to prescribe.

3. Wilderness weather station Important

  • A data collection system that collects data about weather conditions in remote areas. The government of a country with large areas of wilderness deploys several hundred such stations.
  • The instruments measure temperature and pressure, sunshine, rainfall, wind speed and wind direction (ground and air temperature, barometric pressure, 24-hour rainfall).
  • Each instrument is controlled by software that takes parameter readings periodically and manages the data collected.

The station belongs to a larger weather information system of three systems that exchange information (Fig 1.8). The weather station system collects weather data, carries out some initial data processing and transmits it to the data management system. The data management and archiving system collects the data from all of the wilderness weather stations, carries out data processing and analysis, and archives the data. The station maintenance system communicates by satellite with all wilderness weather stations to monitor their health and provide reports of problems.

Stations are unattended and battery-powered, so the software also needs additional functionality: (1) monitor the instruments, power and communication hardware and report faults to the management system; (2) manage the system power, charging batteries whenever environmental conditions permit but shutting down generators in potentially damaging weather such as high wind; (3) support dynamic reconfiguration, where parts of the software are replaced with new versions and backup instruments are switched in after a system failure.

4. iLearn: a digital learning environment Important

  • A system to support learning in schools: a framework in which general-purpose and specially designed learning tools may be embedded, plus applications geared to the learners' needs.
  • The tools are chosen by teachers and learners: general applications such as spreadsheets, learning management applications such as a Virtual Learning Environment (VLE) for homework submission and assessment, games and simulations.
  • It is a service-oriented system: every component is a replaceable service. So it can be updated incrementally as new services become available, and rapidly configured for groups such as very young children who cannot read, or senior students.
  • Services: utility services give basic application-independent functionality used by other services; application services give specific applications (email, conferencing, photo sharing) and educational content (scientific films, historical resources); configuration services adapt the environment with a set of application services and define how services are shared between students, teachers and parents.

Service integration happens at two levels. Integrated services offer an API (application programming interface) that other services can call, so direct service-to-service communication is possible (e.g. authentication). Independent services are simply accessed through a browser interface and operate independently; information is shared only through user actions such as copy and paste, and re-authentication may be needed for each one.

Definitions

  • Software engineering: an engineering discipline concerned with all aspects of software production, from early system specification to maintaining the system in use. Key phrases: engineering discipline and all aspects of software production.
